# PDF++ Sync

**在 Obsidian 中阅读、标注 PDF，并在不同设备间接着上次的位置继续阅读。**

PDF++ Sync 是由 [minLaoGe](https://github.com/minLaoGe) 独立维护的二次开发项目，基于 [Ryota Ushio 的 PDF++](https://github.com/RyotaUshio/obsidian-pdf-plus) **0.40.31** 开发。保留原有 PDF 标注、摘录和笔记联动能力，在此基础上增加可直接在页面编辑的文字批注，以及通过笔记库同步的阅读进度。

本仓库独立发布与迭代，不是原作者的官方版本。原项目及其贡献者为本项目提供了核心代码与设计，感谢他们的工作。原始介绍保存在 [README.upstream.md](README.upstream.md)。

> **当前为开发验证阶段。** 已通过编译、生产构建和模拟跨客户端测试；在 macOS / Obsidian 1.14.4 上验证了文字框新增、修改、保存及进度写入。iOS、Android 与真实跨设备传输仍需验证。欢迎通过 Issues 提交验证结果。

## 能做什么

| 能力 | 说明 | 来源 |
| --- | --- | --- |
| PDF 阅读增强 | 在 Obsidian 内置阅读器上增强使用体验 | 上游 PDF++ |
| 标注与笔记引用 | 将 PDF 内容与 Markdown 笔记、反向链接关联 | 上游 PDF++ |
| 页面文字框 | 点击页面输入文字，双击已保存的文字再次修改；支持字号、颜色与删除 | 本项目新增 |
| 阅读位置记录 | 保存页码、页内位置及缩放比例 | 本项目新增 |
| 跨设备续读 | 同步进度文件后，重新打开 PDF 恢复位置 | 本项目新增 |
| 独立设备记录 | 各设备写入不同文件，减少同一文件的写入冲突 | 本项目新增 |
| 链接优先 | 显式页码、选区等链接优先于续读位置 | 本项目新增 |

**不需要另外安装 PDF++。** 本项目包含其代码，是对原插件的替换版本。

## 安装

目前采用手动安装，未以独立插件身份上架 Obsidian 社区插件市场。

1. 下载 [Releases](https://github.com/minLaoGe/obsidian-pdf-plus-sync/releases) 中的 `main.js`、`manifest.json`、`styles.css`，或下载 ZIP 后解压。
2. 关闭 Obsidian，或先停用现有 PDF++。
3. 如果已经安装 PDF++，备份笔记库内的 `.obsidian/plugins/pdf-plus/`。
4. 将上述三个文件放入 `.obsidian/plugins/pdf-plus/`，保留已有的 `data.json`。
5. 重启 Obsidian，在「设置 → 第三方插件」中启用 **PDF++ Sync**。
6. 在插件设置顶部确认「跨设备 PDF 阅读进度」开启，默认已开启。

桌面端与移动端都需要安装同一版本。iOS、Android 的插件目录访问方式取决于你的笔记库与同步工具配置。

### 从 PDF++ 迁移

当前沿用 `pdf-plus` 插件 ID，以便读取已有设置，安装目录也沿用 `pdf-plus`。因此：

- 这是原 PDF++ 的替换版本，不能作为两个插件同时启用。
- 不需要删除旧设置或重新导入 PDF。
- 从社区市场更新原 PDF++ 可能覆盖本项目的文件。
- 回退时停用本版本，将备份的插件文件放回即可。阅读进度目录不会修改原 PDF。

## 在 PDF 页面上直接写字

1. 在插件设置中开启 **Enable PDF editing**。
2. 点击工具栏 **T**，再双击页面，直接输入文字；已有文字也需双击才进入编辑。新框以一个字宽起步，随文字增加自动变宽，到页面边缘后换行，透明底色保留底图。
3. 用浮动工具条改字号、颜色，拖动左侧手柄移动文字框，拖动两侧圆点调整宽度。
4. 点击 ✓、页面空白处或 `Ctrl/Cmd + Enter` 完成当前编辑；此时是**本机草稿**。
5. 点击顶部 **保存更改** 或按 `Ctrl/Cmd + S`，将所有草稿一次写入 PDF。等待同步工具传输 PDF 后，其他设备才能看到。
6. `Esc` 撤销当前文字框本轮编辑；删除也要点击「保存更改」才写入 PDF。

**0.42.0 重做了交互与保存流程。** 页面内直接输入，批注信息优先复用阅读器缓存；PDF 解析、外观生成和导出移入 Web Worker，多条编辑合并一次写入。草稿保存在客户端本地，重新加载插件后可继续，草稿本身不跨设备同步。编辑浮层接入 [Interact.js](https://github.com/taye/interact.js)（MIT）处理拖动与缩放，沿用 Obsidian 的 PDF.js 阅读器；[架构与开源来源](docs/EDITOR-ARCHITECTURE.md)说明实际集成范围。

这是标准 PDF **FreeText 文字批注**，支持扫描件上的空白区域，不依赖原 PDF 的文字识别。它不会替换原有正文，也不提供 OCR 或全文重排。

文字内容以 Unicode 保存在 PDF 批注中；为了在没有额外字体的移动端离线保存中日文，显示外观使用客户端系统字体绘制为高分辨率图像。文本仍可在本插件内修改，但大倍率放大可能比矢量字柔和。普通 PDF 阅读器可以显示已保存的外观，第三方软件重新编辑时的字体效果取决于其支持。

首次使用此工具修改某个 PDF 前，会在 `PDF++ Sync/backups/<PDF 标识>/before-text-edit.pdf` 保存一份初始备份，不会每次改字都复制整本书。文字批注保存在 **PDF 本身**，其他设备需同步修改后的 PDF。保存时若检测到文件或所编辑文字发生变化，会停止覆盖并提示重新打开。

工具栏另有 **荧光笔 / 高亮选中的 PDF 文本**：先选中可识别的 PDF 正文，再点击此按钮，先预览为本机草稿，最后点击「保存更改」，与文字一起批量写入标准 Highlight 批注。颜色使用 PDF++ 设置的默认高亮色。文字和高亮可混合编辑；扫描图片中的文字需先 OCR 才可选择。高亮写入 PDF 后由原同步工具传输。

保存需要 Web Worker 和 OffscreenCanvas 支持；不支持时保留本地草稿并报告失败。

当前仅在页面显示旋转为 **0°** 时开放放置与编辑，旋转后可以正常阅读已有批注。文字框应位于页面内，最多 5000 字符、字号 6–72；多行文字超出页面时会提示调整位置或内容。

## 书签目录与扫描件高亮（0.43.0）

- 点击工具栏 **书签目录** 图标，打开目录面板，点击 **添加当前页**。
- PDF 阅读器内 **Ctrl/Cmd+P** 添加当前页书签；**Esc** 关闭书签目录。此快捷键在 PDF 内优先于 Obsidian 命令面板，其他位置保留原行为。
- 为书签填写名称及目录，例如 `第一章/重点`，形成可折叠的多级目录；点击条目跳页，右侧按钮改名、移动目录或删除。
- 书签按 PDF 路径识别，保存在 `PDF++ Sync/bookmarks/<PDF 标识>/<书签 ID>.json`，各书签独立文件。同步此目录即可在其他设备看到；删除保存为标记，避免删除记录被误当作旧书签。
- 同一书签被多台设备同时编辑时仍由同步工具处理冲突；移动或重命名 PDF 后不自动迁移书签。
- **选择 PDF 正文**：点击文本光标图标，启用文本选择模式，解除批注覆盖层对拖动选字的干扰，然后选中文字并点击荧光笔。再点一次退出，或点击 T 回到文字批注。
- **框选高亮**：点击带文字的 **框选高亮** 按钮，拖动选取页面区域，松开后暂存高亮并保持模式开启，可连续框选；最后点击「保存更改」与文字一起写入 PDF；支持没有文字层的扫描件。Esc 退出，或再点框选按钮关闭。旁边颜色选择器用于正文和框选高亮，新高亮使用新颜色，已有草稿颜色不变；撤销按钮移除最近一条未保存高亮。模式和颜色在本机记忆。开启 Enable PDF editing。
- 扫描件没有文字层时无法逐字选择，插件会自动切换为框选高亮并提示拖动方式；本版本不含 OCR。高亮保存后需要同步修改后的 PDF。

本次按用户要求仅做 TypeScript 编译与生产打包，书签、文本选择模式及框选高亮交由用户验证。

## 撤销、重做与保存（0.45.0）

- 阅读器内 `Ctrl/Cmd+Z` 撤销，`Ctrl/Cmd+Shift+Z` 重做：本插件的文字新增、输入、移动、缩放、字号、颜色、删除，以及正文/框选高亮共用操作记录；书签增改删也可撤销。
- 连续输入会合并为短文本段；撤销当前输入会结束文字框编辑，双击可继续。普通设置或书签名称输入框保留系统自身的文本撤销。
- `Ctrl/Cmd+S` 或「保存更改」统一将文字和高亮写入 PDF。本次会话已保存的批注也可撤销，撤销结果先作为新草稿，需再次保存才修改磁盘与其他设备。
- 操作记录只在当前插件会话保留。重载后可以撤销恢复的草稿，但不会恢复上次会话的逐步历史；其他软件或原上游独立功能的操作不在此队列内。
- 框选模式保持开启；其他模式也可 **Alt+拖动** 临时框选。首次使用默认启用框选，之后记忆你的模式选择。
- 后台保存时可继续新增框选高亮，新增内容保留为下一批草稿；保存进行中的撤销会等待当前保存完成，再生成逆向草稿。

本次仅编译打包，交互由用户验证；实际跨设备传输由同步工具负责。

## 如何跨设备接着读

插件负责记录与恢复；**文件传输由你现有的笔记库同步工具负责**，本项目不提供账号或云同步服务。

```text
设备 A 阅读 PDF
    ↓ 保存进度
笔记库 / PDF++ Sync / reading-progress / <PDF 标识> / <设备 ID>.json
    ↓ 你的同步工具
设备 B 收到 PDF 和进度文件
    ↓ 重新打开 PDF
恢复最近一次已同步的位置
```

### 统一数据目录

```text
PDF++ Sync/
├── reading-progress/          # 阅读进度：按 PDF 分组、各设备独立记录
│   └── <PDF 标识>/
│       └── <设备 ID>.json
├── backups/                   # 首次添加文字前的 PDF 初始备份
└── tests/                     # 本机验证用的示例，可选
```

升级时自动将旧 `PDF++ Reading Progress/` 目录中有效的记录复制到新目录；旧文件保留为备份，不再由新版写入。所有设备升级后，确认新目录中有进度，再自行归档旧目录。

在所有设备上：

1. 使用同一个笔记库，保持 PDF 的库内相对路径一致。
2. 安装并启用此版本。
3. 让同步工具包含 **PDF 文件**及库根目录的 **`PDF++ Sync/reading-progress/`**。
4. 确认同步规则没有排除 JSON 文件。

例如，电脑读到第 20 页后，停止滚动约一秒，等待同步完成；手机完成同步后重新打开同一 PDF，即可恢复。手机回翻到第 5 页继续阅读，新的记录也可以作为下一次续读位置，而不是永远选最大的页码。

如果进度文件刚刚同步到本机，可点击状态栏的 PDF 进度，或在命令面板执行 **PDF++ Sync: 恢复已同步的 PDF 阅读进度**。切回 PDF 标签页、应用回到前台时，也会检查较新的记录；明确的页码链接优先。已同步文件有新进度时会在状态栏提示，不会在你阅读过程中突然跳页。状态栏“已保存到同步目录”仅表示本机落盘，不表示云端上传完成。

不同同步工具是否同步 JSON、是否启用了附件同步、文件大小是否超过限制，需要在各自设置中确认。**仅同步插件配置，不能替代同步阅读进度目录。**

## 记录与恢复规则

- 保存范围：普通 PDF 标签页；不记录 Markdown 内嵌 PDF 或悬浮预览。
- 写入条件：阅读器聚焦且发生滚轮、触摸、指针或键盘操作；工具栏翻页、输入页码和缩放也会记录。仅打开文件不会主动写入新进度。
- 保存时机：位置变化停止约 500 毫秒后；进入后台或关闭时保存已捕获的导航快照，不重新读取后台位置。
- 保存内容：PDF 的库内路径、页码、页内 PDF 坐标、缩放、设备 ID 与版本时间。
- 存储方式：普通库内 JSON 文件，统一保存在 `PDF++ Sync/reading-progress/`；每个 PDF 一个子目录、每个设备一个记录。直接读取存储中的文件，不依赖 Obsidian 元数据索引已更新。
- 设备标识：保存在客户端本地存储中，不放入同步的插件设置；本地存储不可用时使用临时会话 ID。
- 冲突选择：优先选择版本时间较新的记录，相同时按设备 ID 确定顺序。
- 自动恢复：正常重新打开 PDF 时恢复；明确指定目标位置的链接优先。
- 远端变化：阅读中不会突然被另一台设备的进度拉走，重新打开时才读取。
- 损坏数据：无法解析或未通过校验的记录会被忽略，不阻止 PDF 打开。

## 已知限制

- **跨端实机兼容性仍待验证。** macOS / Obsidian 1.14.4 已验证主要入口；使用跨平台 API 并不意味着 iOS、Android 均已通过验证。
- 离线阅读需要等进度文件同步后，另一端才能续读；不是实时协同。
- 多端同时离线阅读时，无法准确知道未同步设备的真实操作先后。建议开启系统自动校时，避免同时操作同一 PDF。
- PDF 以库内路径识别，移动或重命名后不会自动迁移旧进度。
- PDF 页数发生变化后，超出范围的旧位置不会恢复。
- 手机系统强制结束应用前，尚未写入的最后不足一秒进度可能丢失。
- 依赖 Obsidian 的私有 PDF.js 接口；Obsidian 升级后可能需要适配。
- 进度文件包含 PDF 文件路径；同步该目录时，这些元数据也会传输到你选择的同步服务。

## 本地开发

使用 **Node.js 22.13+** 和 npm。本仓库保留上游代码历史，新增同步逻辑集中在 `src/reading-progress.ts`、`src/sync/`，文字批注逻辑在 `src/free-text/`。

```bash
git clone https://github.com/minLaoGe/obsidian-pdf-plus-sync.git
cd obsidian-pdf-plus-sync
npm ci --ignore-scripts
npm test
npm run build
```

`--ignore-scripts` 用于避免开发依赖下载 Electron 运行时；插件构建由后续 `npm run build` 显式执行。npm 使用 `package-lock.json` 固定依赖。

开发时执行 `npm run dev` 开启构建监听。将生成的 `main.js` 与 `manifest.json`、`styles.css` 复制到测试库的 `.obsidian/plugins/pdf-plus/`，重新加载插件。先在测试库开发，避免直接修改日常笔记库。

| 文件 | 用途 |
| --- | --- |
| `src/reading-progress.ts` | 阅读会话、前后台处理、进度恢复与状态提示 |
| `src/sync/store.ts` | 统一目录、旧记录迁移、磁盘读写与记录校验 |
| `src/free-text/` | 页面文字框 UI、PDF 批注与显示外观、备份及并发修改检查 |
| `src/patchers/pdf-internals.ts` | 在 PDF 加载后挂接进度功能 |
| `src/patchers/pdf-view.ts` | 处理视图恢复与进度优先级 |
| `src/settings.ts` | 阅读进度开关 |
| `tests/reading-progress.mjs` | 模拟客户端与共享库的回归测试 |
| `tests/free-text*.mjs` | PDF 文字批注、备份与并发修改检查 |
| `READING-SYNC.zh-CN.md` | 安装与测试说明 |

### 验证范围

自动化测试覆盖记录校验、确定性排序、被动加载不写入、进度保存、第二客户端恢复、回翻续读、设备独立文件、显式链接优先和损坏记录处理。另外覆盖已有 JSON 的多次更新、工具栏输入、元数据未索引的同步文件、后台关闭快照、旧目录迁移、写入失败重试、乱序写入、Unicode 文字批注增改删、初始备份及文件并发修改检查。测试使用模拟的 Obsidian 环境，不替代实机测试。

建议每次修改后验证：

- 电脑第 20 页 → 同步 → 手机恢复。
- 手机回翻到第 5 页 → 同步 → 电脑恢复。
- 点击指向第 12 页的链接，确认跳到第 12 页。
- 不操作的后台标签页不会覆盖新进度。
- 退出应用、重新启动、横竖屏切换后检查位置。
